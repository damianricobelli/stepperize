The flow always holds its own state. You do not pass the current step or the
data on every render and wait for callbacks to apply them; you give the flow a
starting point, and it tells you about every change.

That exchange uses one object, the **snapshot**: everything a flow needs to
continue later.

```ts
type Snapshot = {
  step: string; // the current step
  history: string[]; // the path taken, which prev() walks back
  data: object; // the data of every step, by id
  complete: string[]; // the steps next() has validated, in that order
};
```

It is plain JSON when your data is. Each binding exports it typed for your
steps, as `Snapshot<typeof checkout.steps>`.

<FrameworkOnly is="angular">
On this page, `stepper` is the value of the signal `injectStepper()` returns:
`this.stepper()` in a class, `stepper()` in a template.
</FrameworkOnly>

<FrameworkOnly is="lit">
On this page, `stepper` is the controller's `value`: `this.stepper.value`.
</FrameworkOnly>

## Save and resume

<FrameworkCode>

```ts framework="react vue svelte solid"
const stepper = checkout.useStepper({
  snapshot: saved,
  onChange: (snapshot) => save(snapshot),
});
```

```ts framework="angular"
readonly stepper = checkout.injectStepper({
  snapshot: saved,
  onChange: (snapshot) => save(snapshot),
});
```

```ts framework="lit"
stepper = checkout.controller(this, {
  snapshot: saved,
  onChange: (snapshot) => save(snapshot),
});
```

</FrameworkCode>

- `snapshot` is where the flow starts. Pass any part of it, for example only
  `{ step: "payment" }` or only `{ data }`.
- `onChange` is called with the whole snapshot after the step, the data or
  the completion changes.

`snapshot` is read **once**, when the flow is created. Passing a different
object later does nothing; that is what [`restore`](#loading-a-draft-later) is
for.

## What onChange reports

| Change | `onChange` |
| --- | --- |
| An accepted `next`, `prev` or `goTo` | Yes |
| A `next()` the schema rejected | Yes: the data that was passed is kept |
| `setData` with a new value | Yes |
| `setData` with the value the step already has | No: nothing changed |
| `validate()` | No |
| `reset`, `restore` | Yes |
| `isPending` or `isFinished` changing | No |
| A move the guard refused | No |

## In the browser, without a mismatch

A server cannot read `localStorage`, so a flow that starts from it would
render differently on the server and in the browser. Start from what both
know, and apply the saved snapshot after mounting.

<FrameworkCode>

```tsx framework="react" title="Checkout.tsx"
function Checkout() {
  const stepper = checkout.useStepper({
    onChange: (snapshot) => localStorage.setItem("checkout", JSON.stringify(snapshot)),
  });

  useEffect(() => {
    const saved = localStorage.getItem("checkout");
    if (saved) stepper.restore(JSON.parse(saved));
  }, []);
}
```

## Saving to a server

`onChange` is also called by `setData`. If you write drafts on every
keystroke, debounce the request.

A draft loaded on the server is the best starting point: the first render
already shows the right step.

<FrameworkCode>

```tsx framework="react" title="Checkout.tsx"
import type { Snapshot } from "@stepperize/react";
import { useDebouncedCallback } from "use-debounce";

type CheckoutSnapshot = Snapshot<typeof checkout.steps>;

// `draft` was loaded on the server and passed as a prop.
function Checkout({ draft }: { draft: CheckoutSnapshot }) {
  const save = useDebouncedCallback((snapshot: CheckoutSnapshot) => api.saveDraft(snapshot), 500);
  const stepper = checkout.useStepper({ snapshot: draft, onChange: save });
}
```

```vue framework="vue" title="pages/checkout.vue"
<script setup lang="ts">
import type { Snapshot } from "@stepperize/vue";
import { useDebounceFn } from "@vueuse/core";
import { checkout } from "~/flows/checkout";

type CheckoutSnapshot = Snapshot<typeof checkout.steps>;

// Fetched on the server and handed to the browser with the page.
const { data: draft } = await useFetch<CheckoutSnapshot | null>("/api/checkout/draft");

const save = useDebounceFn(
  (snapshot: CheckoutSnapshot) => $fetch("/api/checkout/draft", { method: "PUT", body: snapshot }),
  500,
);

const stepper = checkout.useStepper({
  snapshot: draft.value ?? undefined,
  onChange: save,
});
</script>
```

```ts framework="svelte" title="src/routes/checkout/+page.server.ts"
import { loadDraft } from "$lib/server/drafts";
import type { PageServerLoad } from "./$types";

```

```svelte framework="svelte" title="src/routes/checkout/+page.svelte"
<script lang="ts">

  import type { PageProps } from "./$types";

  let { data }: PageProps = $props();
  let timer: ReturnType<typeof setTimeout> | undefined;

  const stepper = checkout.useStepper(() => ({
    snapshot: data.draft ?? undefined,
    onChange: (snapshot) => {
```

```tsx framework="solid" title="src/routes/checkout.tsx"
import { debounce } from "@solid-primitives/scheduled";
import { createAsync, query, type RouteDefinition } from "@solidjs/router";
import { Show } from "solid-js";
import type { Snapshot } from "@stepperize/solid";
import { checkout } from "~/checkout";
import { loadDraft, saveDraft } from "~/lib/drafts";

type CheckoutSnapshot = Snapshot<typeof checkout.steps>;

const getDraft = query(async () => {
  "use server";
  // `null` means nothing was saved; `undefined` means it has not loaded yet.
  return (await loadDraft()) ?? null;
}, "checkout-draft");

export const route = { preload: () => getDraft() } satisfies RouteDefinition;

export default function CheckoutPage() {
  const draft = createAsync(() => getDraft());
  return (
    <Show when={draft() !== undefined}>
      <Checkout draft={draft() ?? undefined} />
    </Show>
  );
}

function Checkout(props: { draft?: CheckoutSnapshot }) {
  // `saveDraft` is a "use server" function: calling it from the browser is a request.
  const save = debounce((snapshot: CheckoutSnapshot) => saveDraft(snapshot), 500);
  const stepper = checkout.useStepper(() => ({ snapshot: props.draft, onChange: save }));

  return <CheckoutSteps stepper={stepper} />;
}
```

```ts framework="angular" title="app.routes.ts"
    path: "checkout",
    component: CheckoutPage,
```

```ts framework="angular" title="checkout.page.ts"
import { Component, inject, input } from "@angular/core";
import { takeUntilDestroyed } from "@angular/core/rxjs-interop";
import { debounceTime, Subject, switchMap } from "rxjs";
import type { Snapshot } from "@stepperize/angular";
import { checkout } from "./checkout";
import { DraftApi } from "./draft-api";

type CheckoutSnapshot = Snapshot<typeof checkout.steps>;

@Component({ selector: "app-checkout-page", template: `…` })
export class CheckoutPage {
  readonly #api = inject(DraftApi);
  readonly #changes = new Subject<CheckoutSnapshot>();
  /** Bound from the route's resolver. */
  readonly draft = input<CheckoutSnapshot | null>();

  readonly stepper = checkout.injectStepper(() => ({
    snapshot: this.draft() ?? undefined,
    onChange: (snapshot) => this.#changes.next(snapshot),
  }));

  constructor() {
    this.#changes
      .pipe(
        debounceTime(500),
        switchMap((snapshot) => this.#api.save(snapshot)),
        takeUntilDestroyed(),
      )
      .subscribe();
  }
}
```

<FrameworkOnly is="vue">
`useFetch` runs on the server and hands its result to the browser in the page
payload, so the browser starts the flow from the same draft without fetching it
again. The top-level `await` comes before `useStepper()`, which is fine in
`<script setup>`; see [Server rendering](/docs/v9/vue/guides/ssr#awaiting-data-first).
</FrameworkOnly>

<FrameworkOnly is="svelte">
`load` runs on the server for the first request, and its result is serialized
into the page, so the browser starts the flow from the same draft. Create the
flow in the page, not in a module: a module is shared by every request on the
server.
</FrameworkOnly>

<FrameworkOnly is="solid">
The `query` runs on the server, and its result is serialized into the page, so
the browser starts the flow from the same draft. `Show` waits for it: the flow
reads `snapshot` once, when it is created, so it must not be created before
the draft has loaded.
</FrameworkOnly>

<FrameworkOnly is="angular">
The resolver runs before the component is created, so the input is set when
the flow reads `snapshot`. Resolved data only reaches inputs with
`withComponentInputBinding()`; without it the input stays `undefined` and the
flow starts on the first step, with no error. With `provideClientHydration()`,
`HttpClient` hands the server's response to the browser, so the resolver does
not fetch the draft twice.
</FrameworkOnly>

<FrameworkOnly is="lit">
A property with `type: Object` is parsed from its attribute as JSON, and the
attribute is in the HTML on the server and in the browser alike. The flow is
created no later than the first update, after the attribute has been read.
</FrameworkOnly>

## Loading a draft later

When the draft arrives after the first render, apply it with `restore`. It
replaces the state without validation or guards, and cancels a move that is
running.

<FrameworkCode>

```tsx framework="react"
useEffect(() => {
  api.loadDraft().then((draft) => {
    if (draft) stepper.restore(draft);
  });
}, []);
```

```ts framework="vue"
onMounted(async () => {
  const draft = await api.loadDraft();
  if (draft) stepper.restore(draft);
});
```

```ts framework="svelte solid"
onMount(async () => {
  const draft = await api.loadDraft();
  if (draft) stepper.restore(draft);
});
```

```ts framework="angular"
readonly #api = inject(DraftApi);
readonly #destroyRef = inject(DestroyRef);

constructor() {
  afterNextRender(() => {
    this.#api
      .load()
      .pipe(takeUntilDestroyed(this.#destroyRef))
      .subscribe((draft) => {
        if (draft) this.stepper().restore(draft);
      });
  });
}
```

```ts framework="lit"
async firstUpdated() {
  const draft = await api.loadDraft();
  if (draft) this.stepper.value.restore(draft);
}
```

</FrameworkCode>

`restore` replaces the parts you pass and keeps the others:

| Call | Effect |
| --- | --- |
| `restore(snapshot)` | Replace everything. |
| `restore({ data })` | Replace the data of every step; stay on the current step. |
| `restore({ step: "review" })` | Go to a step without validation or guards. |
| `restore({ complete: [] })` | Clear the completion. |

Each part is replaced as a whole: `restore({ data: { shipping } })` leaves the
other steps without data. To change one step, use `setData`.

## Old snapshots

Flows change. When a saved snapshot names a step that no longer exists, it is
dropped from `step`, `history` and `complete`, and the flow starts on the
first step if `step` was the one that disappeared. A snapshot from an older
version of your flow never throws.

The data of each step is not checked when it is loaded. It is validated like
any other data, the next time `next()` runs on that step.

A snapshot holds what was typed, not the schemas' output, so a step loaded as
complete has no entry in `stepper.output` yet. The `next()` that finishes the
flow validates those steps once more before calling `onFinish`. If the saved
data no longer passes, because the schema changed since, the flow does not
finish: `next()` resolves with `reason: "invalid"`, the step stops being
complete and `stepper.issues(id)` says why. To find out earlier, call
`stepper.validate(id)` after loading the draft.

`restore` keeps the output of every complete step whose data it did not
replace, so `restore({ step: "review" })` loses nothing.

## Starting over

`reset()` goes back to the snapshot the flow started with, and cancels a move
that is still running. Remember to delete your saved copy: `reset()` reports
the fresh snapshot through `onChange` like any other change.

<FrameworkCode>

```ts framework="react vue svelte solid"
function startOver() {
  stepper.reset();
  localStorage.removeItem("checkout");
}
```

```ts framework="angular"
startOver() {
  this.stepper().reset();
  localStorage.removeItem("checkout");
}
```

```ts framework="lit"
#startOver() {
  this.stepper.value.reset();
  localStorage.removeItem("checkout");
}
```

</FrameworkCode>

## Reading the snapshot

`stepper.snapshot()` returns the current one at any time, for example to send
it with a support request, or to read the completed steps.

## What not to save

A snapshot contains everything the steps stored. Remove what should not be
written to storage before saving it.

```ts
onChange: (snapshot) => {
  const { payment: _payment, ...data } = snapshot.data;
  localStorage.setItem("checkout", JSON.stringify({ ...snapshot, data }));
},
```
