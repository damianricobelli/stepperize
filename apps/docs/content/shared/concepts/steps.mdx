The definition is the contract for the whole flow. The stepper, `match`, the
data of each step, the `next` map and the primitives all use these same ids,
and TypeScript knows them as the union `"shipping" | "payment" | "review"`.

On this page, `stepper` is the value of the signal `injectStepper()` returns:
in a template, `stepper()`.
</FrameworkOnly>

<FrameworkOnly is="lit">
On this page, `stepper` is the controller's `value`: `this.stepper.value`.
</FrameworkOnly>

## Step ids

Ids are what you save, put in the URL and branch on. Pick ones that describe
the business step, not the current label or position.

| Good | Avoid | Why |
| --- | --- | --- |
| `"shipping"` | `"Step 1"` | Reordering steps would change its meaning. |
| `"payment"` | `"Pay now"` | Copy changes; ids should not. |
| `"review"` | `"confirm-2026"` | Generated ids cannot be typed or bookmarked. |

Ids must be unique. An empty list or a repeated id throws
[SZ103](/docs/v9/core/errors#sz103) when the first flow is created from the
definition: the first component that uses it, or the first `create()`.

## Your own fields

Two fields have a meaning for the library:

| Field | Used for |
| --- | --- |
| `schema` | Types the step's data, and `next()` validates against it. See [Validation](/docs/v9/:framework/guides/validation). |
| `title`, `description` | Shown by the title and description primitives. A string `title` is also what screen readers hear when the step changes. |

Everything else (`icon`, `optional`, `estimatedMinutes`, a component) is yours.

## Define once, at module scope

A definition holds no state. It is the description of the flow, plus what your
framework needs to use it. Create it once, in a module, outside your
components, and import it where you need it.

<FrameworkCode>

```tsx framework="react"
// Wrong: a new definition on every render. Its Provider is a new component
// each time, so React remounts everything below it with a new, empty flow.
function Checkout() {
  const checkout = defineStepper([{ id: "shipping" }, { id: "payment" }]);
  return <checkout.Provider>{/* ... */}</checkout.Provider>;
}
```

```vue framework="vue" title="Checkout.vue"
<script setup lang="ts">
import { defineStepper } from "@stepperize/vue";

// Wrong: a new definition for every instance of the component. No other
// component can import it, so none can read this flow.
const checkout = defineStepper([{ id: "shipping" }, { id: "payment" }]);
const stepper = checkout.useStepper();
</script>
```


Every flow created from a definition is independent, so one definition can
back several flows on a page.

## Keep ids literal

Ids stay literal when the array is written inline. If you build the array
first, add `as const`, or the ids widen to `string` and you lose the checks.

```ts
// Ids are string: nothing is checked.
const steps = [{ id: "account" }, { id: "profile" }];
const loose = defineStepper(steps);

// Ids are "account" | "profile".
const inline = defineStepper([{ id: "account" }, { id: "profile" }]);

const list = [{ id: "account" }, { id: "profile" }] as const;
const pinned = defineStepper(list);
```

## Fields that only some steps have

`stepper.current` is the union of all your steps. A field that exists on some
steps only is not available until you know which step you are on. `match`
narrows for you:

```ts title="signup.ts"
export const signup = defineStepper([
  { id: "account", title: "Account", help: "We never share your email." },
  { id: "done", title: "All set" },
]);
```

<FrameworkCode>

```tsx framework="react" title="Body.tsx"
import { signup } from "./signup";

export function Body() {
  const stepper = signup.useStepperContext();
  return stepper.match({
    account: (step) => <p>{step.help}</p>,
    done: (step) => <p>{step.title}</p>,
  });
}
```
