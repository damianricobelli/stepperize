---
title: Shared state
description: One flow followed by several elements.
---

`checkout.controller(this, options)` gives one element its own flow. When the
step list, the current panel and the buttons are different elements, create the
flow once and let each element follow it.

A controller takes either options, and owns a new flow, or an existing flow,
and follows it:

```ts
const owner = checkout.controller(this, { linear: true }); // owns a flow
const follower = checkout.controller(this, flow);          // follows one
```

A follower updates its host on every change and unsubscribes when the host is
disconnected, exactly like an owner. It never replaces the flow's options.

## A flow in a module

For a flow that lives as long as the page, create it in a module and import it
wherever it is needed:

```ts title="checkout-flow.ts"
import { checkout } from "./checkout";

export const checkoutFlow = checkout.create({ linear: true, onFinish: placeOrder });
```

```ts title="checkout-header.ts"
import { html, LitElement } from "lit";
import { checkout } from "./checkout";
import { checkoutFlow } from "./checkout-flow";

class CheckoutHeader extends LitElement {
  stepper = checkout.controller(this, checkoutFlow);

  render() {
    const stepper = this.stepper.value;
    return html`<p>Step ${stepper.index + 1} of ${stepper.steps.length}</p>`;
  }
}
customElements.define("checkout-header", CheckoutHeader);
```

## A flow from a parent element

When each instance of a parent needs its own flow, let the parent own it and
hand it down as a property:

```ts
class CheckoutPage extends LitElement {
  stepper = checkout.controller(this, { linear: true });

  render() {
    return html`
      <checkout-header .flow=${this.stepper.flow}></checkout-header>
      <checkout-body .flow=${this.stepper.flow}></checkout-body>
    `;
  }
}
```

```ts
class CheckoutHeader extends LitElement {
  static properties = { flow: { attribute: false } };
  declare flow: Flow<typeof checkout.steps>;
  stepper?: ReturnType<typeof checkout.controller>;

  willUpdate() {
    // Only once the flow has arrived: without one, `controller` would create its own.
    if (this.flow) this.stepper ??= checkout.controller(this, this.flow);
  }
}
```

`Flow` is a type exported by `@stepperize/lit`.

[`@lit/context`](https://lit.dev/docs/data/context/) works too: provide
`this.stepper.flow` and pass what `ContextConsumer` receives to
`checkout.controller`, once it has a value. Stepperize does not depend on it.

## Reading only what you need

A Lit element re-renders as a whole and only touches the DOM that changed, so
there is no selector argument. For a derived value, compute it in `render()`.

## Outside an element

`checkout.create()` returns the same state machine with `get()` and
`subscribe()`, for tests, servers and plain custom elements.
