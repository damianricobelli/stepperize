---
title: The URL as the current step
description: Keep the step in the URL with Solid Router, in both directions.
---

The `step` option makes the flow follow a value that lives somewhere else. Pass
the options as a function so they are read again when the route changes.

```tsx title="src/routes/checkout/[step].tsx"
import { useNavigate, useParams } from "@solidjs/router";
import { checkout } from "~/checkout";

export default function CheckoutPage() {
  const params = useParams();
  const navigate = useNavigate();

  const stepper = checkout.useStepper(() => ({
    linear: true,
    // The URL moves (a link, the back button): the flow follows.
    step: params.step,
    // The flow moves: push the new step.
    onChange: (snapshot) => {
      if (snapshot.step !== params.step) navigate(`/checkout/${snapshot.step}`);
    },
    // The URL asks for a step the flow cannot be on: correct it without a history entry.
    onInvalidStep: (current) => navigate(`/checkout/${current}`, { replace: true }),
  }));

  return <CheckoutSteps stepper={stepper} />;
}
```

- Following the URL is a `goTo`: `linear` and the `guard` still apply, so a
  deep link cannot skip validation.
- `onInvalidStep` is called for unknown ids, for steps `linear` does not allow
  yet and for moves the guard refused.
- On the server the flow starts on the URL's step when that is allowed, and no
  callback runs until the page is mounted.

A query parameter works the same way with `useSearchParams`.
