---
title: Errors and warnings
description: Every diagnostic code, what it means and how to fix it.
---

Diagnostics carry a stable code and a link to this page. Warnings appear only
in development and are removed from production builds; errors are thrown in
both.

The examples below use the React names (`Stepper.Trigger`, `Stepper.Item`,
`useStepperContext()`). The other bindings emit the same codes for the same
mistakes with their own names: a trigger directive in Angular or Lit, a
`stepper-trigger` part in HTML, `injectStepperContext()` or
`useStepperContext()` for a missing provider.

## SZ001

**Warning.** A primitive received a `render` function that did not put the
props it was given on an element. The ARIA attributes, ids, handlers and `ref`
are missing from the page.

```tsx
// Wrong: the props are dropped.
<Stepper.Next render={() => <Button>Continue</Button>} />

// Right
<Stepper.Next render={(props) => <Button {...props} />}>Continue</Stepper.Next>
```

If you spread into your own component, it must forward the `ref` to its
element.

In Vue the same warning means a primitive with `as-child` could not hand its
attributes to one element: its default slot has no element or component, has
more than one (only the first is rendered), the component it holds does not
put the attributes on an element, or an `as-child` List's element already has
children of its own while the `#item` slot was meant to fill it.

```vue
<!-- Wrong: only text in the slot. -->
<Stepper.Next as-child>Continue</Stepper.Next>

<!-- Right -->
<Stepper.Next as-child><MyButton>Continue</MyButton></Stepper.Next>
```

In Svelte it means a `child` snippet did not spread the `props` it received
onto an element.

```svelte
<Stepper.Next>
  {#snippet child({ props })}
    <MyButton {...props}>Continue</MyButton>
  {/snippet}
</Stepper.Next>
```

In Solid it means an `as` component did not spread its props, `ref` included,
onto an element.

In Lit it is an error, not a warning: a primitive was used outside an opening
tag. They are element directives, written next to the attributes, as in
`<ol ${stepper.list()}>`.

## SZ002

**Warning.** A `Stepper.Trigger` has no accessible name. `Stepper.Indicator` is
hidden from screen readers, so a trigger that only contains one is announced as
an unnamed button.

```tsx
<Stepper.Trigger aria-label={step.title}>
  <Stepper.Indicator />
</Stepper.Trigger>
```

## SZ003

**Warning.** A `Stepper.Trigger` is rendered outside `Stepper.List`. Keyboard
navigation and the list semantics depend on the list. Move the trigger inside
it, or use a plain button that calls `goTo`.

## SZ004

**Warning.** A trigger or a panel is rendered in a different shadow root than
the stepper's root. Tabs, panels and the focus hand-off are tied together by
ids, and an id reference (`aria-controls`, `aria-labelledby`) cannot cross a
shadow root.

It comes from Lit, where a child component can render parts in its own shadow
root. Render triggers and panels in the same shadow root as `root()`; the
other parts (list, item, indicator, prev, next) may live in a child component.

## SZ005

**Warning.** A trigger is not a `<button>`. Enter and Space do not press a
`<span>` or a `<div>`, and it cannot be disabled. Every binding checks the
element a trigger ends up on, in development: the one a `render` function,
`as-child`, a `child` snippet or an `as` component renders, the element an
Angular or Lit trigger directive is written on, and the `stepper-trigger` part
`bindStepper` enhances. A link with an `href` passes, since the keyboard can
press it.

```tsx
// Wrong
<Stepper.Trigger render={(props) => <span {...props} />}>Account</Stepper.Trigger>

// Right
<Stepper.Trigger>Account</Stepper.Trigger>
```

```html
<!-- Wrong -->
<span data-component="stepper-trigger">Account</span>

<!-- Right -->
<button data-component="stepper-trigger">Account</button>
```

## SZ100

**Error.** A component read a flow that is not provided above it.

- `useStepperContext()` needs the `Provider` or `Stepper.Root` of the same
  definition as an ancestor. A provider of another definition does not count.
- The primitives need `Stepper.Root`.
- Angular: `injectStepperContext()` needs a `provideStepper()` of the same
  definition, or a `[stepperRoot]` bound to one of its steppers, above it, and
  the primitive directives need a `[stepperRoot]`.
- Lit: the other parts need the `root()` directive on an element that contains
  them.

If the component only needs its own flow, use `useStepper()` instead.

## SZ101

**Error.** A primitive that belongs to a step was rendered outside
`Stepper.Item`, or a `Stepper.Item` has no `step`.

`Trigger`, `Indicator` and `Stepper.useItem()` need an item around them. An
item gets its step from the `Stepper.List` function, or from its `step` prop:

```tsx
<Stepper.List>{(_step) => <Stepper.Item>…</Stepper.Item>}</Stepper.List>

<Stepper.Item step="payment">…</Stepper.Item>
```

In HTML bound with `bindStepper`: a part that needs a step has no `data-step`,
on itself or on its `stepper-item`.

## SZ102

**Error.** A step id does not exist in the definition. It is thrown by `goTo`,
`setData`, a `next` branch that returns an unknown id, `Stepper.Item` and
most content parts.

`goTo`, `setData` and `Stepper.Item` throw it directly. So do a content part
for a step that is not in the definition (`Stepper.Content` in Vue, Svelte and
Solid, Angular's `stepperContent`, Lit's `content()`) and `bindStepper` for a
`data-step` that is not in the flow. A `next` branch that returns an unknown id
makes the `next()` promise reject with it.

Where ids are typed, TypeScript catches this at compile time; it usually means
a value was cast, or came from outside, such as a URL. Ids written in an HTML
attribute (`data-step`) or an Angular directive input without a
[`StepperRegistry`](/docs/v9/angular/api/primitives#stepperregistry) are plain
strings and are only checked when the page runs. For outside values use the
[`step` option](/docs/v9/react/guides/url): it ignores unknown ids and calls
`onInvalidStep` so you can correct the source.

## SZ103

**Error.** The list of steps is not valid: it is empty, or two steps share an
`id`.

## SZ104

**Error or warning.** A flow was created where nothing owns it, so nothing
would ever destroy it.

- Svelte, an error in the browser: `useStepper()` was called outside a
  component's initialisation, for example in a `.svelte.ts` module. The server
  does not check it, so never call it at module scope. Use
  `fromFlow(definition.create())` there.
- Vue, a warning: `useStepper()` ran without a component instance or an effect
  scope, typically after an `await` in a hand-written async `setup()`. Call it
  before the first `await`, or inside an `effectScope()` that you stop.
